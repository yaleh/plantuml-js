# Visual review rubric

Score each item 1–5 (1 = poor, 3 = acceptable, 5 = excellent) on the S / M / L /
XL sample renders. Scores are assigned by a human or external reviewer looking
at the rendered images, not by the implementer.

| # | Item | What a 5 looks like |
| --- | --- | --- |
| 1 | Hierarchy | The eye lands on class names first, then packages and edges; ink weight reflects importance. |
| 2 | Typography | Clear title / member / label ladder; comfortable padding; nothing hugs a border. |
| 3 | Colour and semantics | Restrained palette; each colour has one meaning (red only for cycles). |
| 4 | Lines and arrows | Strong vs. weak relations are distinguishable; arrowheads visible; corners clean. |
| 5 | Spacing, rhythm and alignment | Same-row nodes align; sizes sit on the 8px grid; consistent padding. |
| 6 | Whitespace and density | Neither cramped nor sparse; structure readable at a glance. |
| 7 | Scale adaptation | Detail level suits the diagram size (members on S, names on XL). |
| 8 | Consistency | The same element is drawn the same way everywhere. |
| 9 | Accessibility | Contrast ≥ WCAG AA; meaning never carried by colour alone. |
| 10 | Overall impression | Looks designed rather than dumped; fit to show in documentation. |
